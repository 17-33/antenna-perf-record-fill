## 一、为什么顺序 = 切面

测试端实际作业顺序被约定成发图顺序：

```
每频点 2 张：第 1 张 方位(AZ)  第 2 张 俯仰(EL)
```

**两张各落自己那一行的两组列**，不是都落同一行：

| | 第 1 张 = 方位 | 第 2 张 = 俯仰 |
|---|---|---|
| 落格 | `D E F J K L M` | `G H I N O P Q` |
| 含义 | 方位主瓣/旁瓣/3dB/10dB | 俯仰主瓣/旁瓣/3dB/10dB |

---

## 二、频点顺序

| 段 | 顺序 | 落到行 |
|---|---|---|
| **发射 TX** | `47.2 → 48 → 49.2 → 49.7 → 49.72 → 49.75 → 49.78 → 49.8` | 13 → 20 |
| **接收 RX** | `37.5 → 37.75 → 38 → 39.95 → 39.975 → 40 → 40.025 → 40.05` | 5 → 12 |

**RX 的 CF 换算**：台面 `CF = 射频频点 − 34.5`（中频！）。填表用**射频**找行。
例：图上 CF=3.0 GHz → 射频 37.5 GHz → 行 5。

## 三、顺序发反的后果（且现有校验查不出来）

| 校验 | 会报错吗 |
|---|---|
| 数值合法性 | ❌ 看起来完全正常 |
| 增益反算 `T` | ❌ 仍算得出，只差零点几 dBi |
| `analyze` 合格判定 | ❌ 仍可能"合格"（门限有裕量） |
| `crosscheck` | ❌ 通过（它只比"截图值 vs 表内值"，两边同源） |
| `diff` / `audit` / `zipcheck` | ❌ 全过 |
| **真实伤害** | **方位与俯仰整批对调，32 行全错，正确性只能靠重新判读发现** |

> **这一环只能靠流程兜底，不能靠校验兜底。**

## 四、三道防线（**均为现行主流程之外的补充**，非强制卡点）

> ⚠️ 本节三条**均非 `SKILL.md` §7 SOP 的步骤**。`check_pairs.js` 不在主流程里，
> 需**手动主动调用**才生效。用不用由人决定。

```bash
# ① 切面时序门禁 —— 需手动跑
node scripts/check_pairs.js --dir=<本批截图目录>
#    退出码 1 → 立即停，把异常清单报给用户
#    异常码：CONFLICT / EXTRA / GAP_TIGHT / DUP / BAD_CF / NO_TS

# ② CF 自校验 —— 需自己核对
#    TX:  CF = 频点        RX:  CF = 频点 − 34.5
#    对不上 → 报"期待第 N 槽 = XX GHz，实际 CF = YY GHz"，不硬填

# ③ 协议落盘
#    <机器>/填写协议.md：频点顺序 + 图序 + 单位 + 口径 + 进度对照表
```

### ⚠️ 三道仍有缺口

时序只证明「**哪张先、哪张后**」，证明不了「**先的一定是方位**」。
**整批系统性颠倒抓不出来**（作业时从头到尾都先俯仰后方位）。

## 四之二、🚫 弃权规则：判断不了切面就别填（用户 2026-10-06 定）

> **这是硬规则，不是建议。** 与前面三道防线不同 —— 它**不增加任何步骤**，
> 只是把"不确定"从「猜一个 / 按默认推」改成「**停手**」。

### 判为「判断不了」的情形 → 一律不填

| # | 情形 | 依据 |
|---|---|---|
| 1 | 读不到仪器状态栏时间戳 | `NO_TS` |
| 2 | 同频两张时间戳相同，或间隔 < 15 s | `GAP_TIGHT`（疑似重复投喂） |
| 3 | **文件名标的切面与时序推断矛盾** | `CONFLICT` |
| 4 | CF 落到 16 个频点之外（连频点都对不上） | `BAD_CF` |
| 5 | 用户没说明、文件名没标、时序也无法判定 | —— |

### 可以填的情形

- **用户明说"方位"/"俯仰"**（最高优先级）—— 即使只有一张图、即使没有对偶图，**照填**
- 文件名带 `AZ` / `EL` 标识
- 有对偶图且时序**唯一可分辨** + 有填写协议背书（先方位后俯仰）

### 判断不了时的动作

1. **停手**，不写任何数据格
2. 报出**缺哪一项证据**（不要只说"不确定"）—— 是时间戳读不到？还是两图矛盾？还是没人说明？
3. 列出该频点**已填 / 未填**清单
4. **已落格的数据保持不动** —— 绝不半途去改已经填好的行
5. 等用户答复

### 明确禁止

- ❌ 猜一个填进去
- ❌ "先填着，回头再改"
- ❌ 按相邻频点**类推**切面
- ❌ **只填一侧**（方位填了、俯仰留空）—— 这会让增益公式在单边数据下算出假值

> 单边填充比不填更危险：`T = 10·LOG10((R+S)/2)` 缺一侧时仍会算出一个数，
> 看起来正常、实则无意义 —— 属于本卡第二节说的"查不出来"那一类。

## 五、根治办法：让切面在图外留痕

给测试端的建议（性价比排序，**当前均未落地**）：

1. **文件名带 `AZ` / `EL`** ← 最省事，`CONFLICT` 检查立刻生效
2. **屏幕上显示当前切面**（截图自带，不依赖外部信息）
3. **发消息时标两个字**（"方位"/"俯仰"）← 零成本兜底

> 有了 ① 或 ②，系统性颠倒也变成可检项。

## 六、发图方注意事项

| # | 建议 | 原因 |
|---|---|---|
| 1 | **按频点成对发**，别拆开 | 单张图无法自证切面（`plane` 显示 `—`） |
| 2 | **顺序别中途改** | 改了就必须说明"从第几张重新开始" |
| 3 | **收到即归档**，用 `cp` 不用 `mv` | 剪贴板/微信目录会被系统清理；源文件留着可回溯 |
| 4 | **同名文件看电平区分路径** | `39.95.jpg` 在两个目录都有且内容不同 |
| 5 | **散件照发** | "发几张填几张"，一张也收 |
| 6 | **重发同一张会被判重跳过** | SHA256 相同不重填；想重填须先声明"这是新数据" |

## 七、其他两张表的顺序

| 工作表 | 顺序 | 落格 | 卡点 |
|---|---|---|---|
| **跟踪精度** | 截图编号 `n` → **行 `n+3`** | `B{n+3}` / `C{n+3}` | 口径未定（姿态角 vs 传感器角），**暂不填** |
| **前向链路** | RX 8 频点顺序同上 | 行 3–10 | LNB 衰减 0.0 vs 表头「7」冲突，**暂不填** |

## 八、换机器/换协议时建议复核三项

- [ ] 发图顺序是否与**本机实际作业顺序**一致
- [ ] 仪器状态栏是否**稳定显示秒级时钟**（时序门禁的前提）
- [ ] 截图文件名/画面是否**带切面标识**（决定 §19.6 缺口能否补上）
