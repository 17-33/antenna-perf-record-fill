## 1. 目的与适用范围

### 1.1 目的

统一「电性能测试原始截图 → 检测记录表」的判读口径与落表动作，使：

- **同一批数据，任何人填出来的结果完全一致**（可复现）；
- **每一个填入值都能追溯到一张具体截图**（可追溯）；
- **每一次填写都经过机器校验，不留隐性错误**（可验证）；
- 换人、换机型、换模板时能快速重建能力（可迁移）。

### 1.2 适用范围

适用于 1.8 m 一体化信关站出厂前的电性能数据落表作业，覆盖：

| 序号 | 数据类型 | 来源截图/文件 |
|---|---|---|
| 1 | 方向图（方位/俯仰，RX/TX） | `架标测试\接收\<F>方位.jpg`、`\<F>俯仰.jpg`、`架标测试\发射\<F>方位/俯仰.jpg` |
| 2 | EIRP 正向功率 P | `架标测试\发射\<F>功率.jpg`（信关站管理系统网页） |
| 3 | 前向链路（接收）标定 | `接收链路标定\LNB到频谱仪\`、`\LNB到地基基站IN1\`、`\LNB到测控基带XS05\` |
| 4 | 跟踪精度 | `跟踪精度\<n>.png`（BAT Pro 界面截图） |
| 5 | 旁证类（不入表） | `EIRP\八通道功率.png`、`EIRP\BUC功率.png` |

### 1.3 不适用

- 天线的**装配**作业（见装配 SOP）；
- 射频指标**仲裁/复测判定**（超差后如何处理由技术负责人判定，本 SOP 只负责"如实、准确落表"）；
- 非 1.8 m 机型。换机型必须先执行 `references/新机型适配清单.md` 的核对流程。

### 1.4 一条铁律

> **永不改动原始记录表原文件。** 一切写入只发生在**副本**上；每批产出**一个新的、可回退的文件**。

## 3. 术语与符号

| 术语 | 含义 | 备注 |
|---|---|---|
| **CF** | Center Frequency，频谱仪中心频率 | 接收类截图上显示的是**中频** |
| **射频** | 实际工作频率 | 接收类：`射频 = CF + 34.5`（LO） |
| **LO** | 本振频率 | 接收 **34.5 GHz**；发射 **44.2 GHz** |
| **RX / TX** | 接收 / 发射 | RX 37.5–40.05 GHz；TX 47.2–49.8 GHz |
| **ΔdB** | marker 相对主瓣峰值的电平差 | **认列的唯一依据**（不是 marker 编号） |
| **姿态角** | BAT Pro「ANT 状态」面板的姿态读数 | **跟踪精度表的唯一口径** |
| **零扫** | Zero Span，固定频点看时间 | SWT 20 s、0.1°/s |
| **旁瓣** | 主瓣外的次级波瓣 | −14 ~ −18 dB 区间的 marker |
| **3dB / 10dB 点** | 半功率点 / 十分之一功率点 | 对应波束宽度 |
| **RMS** | 均方根 | 跟踪精度 δ 的计算方式 |
| **σ** | 面型标准偏差 | 一台天线一个值 |
| **Lm / Lc / Lf / Lfeed** | 面精度损耗 / 天线罩损耗 / 波导损耗 / 馈线损耗 | `L = Lf + Lfeed + Lc` |
| **`\`** | 该路径本次未接线 | 原表写法，**照写**，不填空、不写 0 |

## 7. 详细作业步骤 S1–S9

### S1 工作区准备

| 项 | 内容 |
|---|---|
| 输入 | 原始记录表、本次全部截图 |
| 动作 | ① 新建 `<WORK>`；② 原始记录表复制进 `<WORK>/原始/`，**原位置文件不动**；③ 建 `批次/`、`报告/` 目录；④ 首次使用先跑 §5.4 自测 |
| 命令 | `cp "<原始记录表.xlsx>" "<WORK>/原始/"` |
| 输出 | 工作副本（用于每次填写的输入） |
| 判据 | `原始/` 内文件 **SHA256 与源文件一致**；记录该 SHA256 备查 |
| 常见错误 | 直接在被占用的共享盘上操作 → 写入失败 |

> **自证**：`node scripts/zipcheck.js "<原始记录表.xlsx>"` 应报通过；这一步同时确立"基线完好"。

---

### S2 截图清点与登记

| 项 | 内容 |
|---|---|
| 输入 | 本次测试的截图全集 |
| 动作 | ① 按 §5.6 目录归类；② 逐张登记：文件名 / 目录 / 截图时间戳 / 大小 / SHA256；③ **SHA256 判重** |
| 输出 | 截图登记表（附录 D） |
| 判据 | 每张图有且仅有一条登记记录；重复文件被标记为"与批次 N 同一文件" |
| 常见错误 | 漏登记 → 后续"表里少一行"却找不到漏在哪 |

**必须登记的字段**

```
序号 | 目录 | 文件名 | 截图时间戳 | 图类型 | SHA256(前12位) | 是否重复 | 处理
```

**重复投喂处置**

> 同一张图被再次发来时，用 SHA256 判重，**不重复填写**，但在日志行里注明"与批次 N 同一文件"。

---

### S3 判读

**逐张记录以下六项，一项都不能少：**

| # | 判读项 | 说明 |
|---|---|---|
| 1 | **图类型** | 方位图 / 俯仰图 / 功率网页 / 跟踪精度面板 / 链路标定扫频 |
| 2 | **CF 及换算后的射频** | 接收类必须 `射频 = CF + 34.5` |
| 3 | **marker 表全部行** | 编号 + 频率 + 电平 + 相对电平（ΔdB） |
| 4 | **右上角注释** | 操作员常在此写备注（如"装罩/未装罩"） |
| 5 | **状态栏告警** | 如温漂告警，需记录并在报告备注 |
| 6 | **时间戳** | 用于同行判定与重复判定 |

**小字必须放大核对（≥2× 裁剪）；条件允许时与 OCR 交叉验证。**

#### S3.1 三条判读总则（一切判读的基础）

**总则一：时间 → 角度**

> 方向图为**零扫**（Zero Span、SWT 20 s、0.1°/s），故 `|Δ时间(s)| ÷ 10 = 角度(°)`
> 例：`1.4146 s → 0.14146°`（半功率点半边角）

**总则二：按 ΔdB 语义认列，不要按 marker 编号认**

| ΔdB 语义 | 落的列族 |
|---|---|
| `M1`（绝对 dBm） | M 列（主瓣绝对电平） |
| `≈ −3 dB` | **3dB 列** |
| `≈ −10 dB` | **10dB 列** |
| `−14 ~ −18 dB` | 旁瓣列 |
| `−20 dB 以下远区` | **不填** |

> ⚠️ 不同操作员编号习惯不同；**按编号认列是本流程最常见的出错原因**。

**总则三：符号定方向**

| Δ时间符号 | 方向 |
|---|---|
| **负** | 方位**左 L** / 俯仰**下 D** |
| **正** | 方位**右 R** / 俯仰**上 U** |

> 扫法是"逆时针退 1° → 顺时针扫 2°"，故时间轴负端 = 左/下。**屏幕上不写左右上下**，必须靠符号推。

#### S3.2 逐类截图判读卡

| 截图 | 判读要点 | 落到 |
|---|---|---|
| `架标测试\接收\<F>方位.jpg` | CF 是**中频**，射频 = CF + 34.5 | 方向图 RX 行 `D E F J K L M` |
| `架标测试\接收\<F>俯仰.jpg` | 同上 | 方向图 RX 行 `G H I N O P Q` |
| `架标测试\发射\<F>方位/俯仰.jpg` | CF **即**射频 | 方向图 TX 行（同上分方位/俯仰） |
| `架标测试\发射\<F>功率.jpg` | 网页，**页面不显示频率**（靠文件名）；读"正向功率 dBm" | EIRP `J` 行 = `dBm − 30` |
| `接收链路标定\LNB到频谱仪\<F>` | 扫频、峰值游标 `M1[1]` | 前向链路 `B` 列 |
| `...\LNB到地基基站IN1\<F>` | 电平 −14 ~ −16 dBm | 前向链路 `D` 列 |
| `...\LNB到测控基带XS05\<F>` | 电平 −20 ~ −22 dBm | 前向链路 `C` 列 |
| `跟踪精度\<n>.png` | BAT Pro「**ANT 状态**」面板的**姿态**角（**不是**传感器/编码器） | 跟踪精度 `B{n+3}` / `C{n+3}` |
| `EIRP\八通道功率.png`、`EIRP\BUC功率.png` | ACLR 页 / 另一次后台截图 | **不入表**，仅旁证 |

**输出**：每张图一行「图名 → 判读结果（类型/射频/marker 明细/角度/方向）」。

### S4 定位：把判读结果翻译成单元格清单

> **这一步完成前，不写任何一个值。**

#### S4.1 行 ↔ 频点（查表定行）

**方向图**

| 行 | 频点 | 行 | 频点 | 行 | 频点 | 行 | 频点 |
|---|---|---|---|---|---|---|---|
| 5 | 37.5 | 9 | 39.975 | 13 | 47.2 | 17 | 49.72 |
| 6 | 37.75 | 10 | 40 | 14 | 48 | 18 | 49.75 |
| 7 | 38 | 11 | 40.025 | 15 | 49.2 | 19 | 49.78 |
| 8 | 39.95 | 12 | 40.05 | 16 | 49.7 | 20 | 49.8 |

- **5–12 = RX**（LO 34.5）；**13–20 = TX**（LO 44.2）

**其余四张表**

| 表 | 数据行 | 行 ↔ 频点/次数 |
|---|---|---|
| EIRP-公式法 | 4–11 | 47.2 / 48 / 49.2 / 49.7 / 49.72 / 49.75 / 49.78 / 49.8（TX） |
| GT-公式法 | 4–11 | 37.5 / 37.75 / 38 / 39.95 / 39.975 / 40 / 40.025 / 40.05（RX） |
| 跟踪精度 | 4–13 | 第 1~10 次（**截图编号 n → 行号 n+3**） |
| 前向链路（接收）标定 | 3–10 | 37.5 … 40.05（RX） |

#### S4.2 接收类频点换算（`射频 = CF + 34.5`）

| 射频 GHz | CF GHz | 射频 GHz | CF GHz |
|---|---|---|---|
| 37.5 | 3.0 | 39.975 | 5.475 |
| 37.75 | 3.25 | 40 | 5.5 |
| 38 | 3.5 | 40.025 | 5.525 |
| 39.95 | 5.45 | 40.05 | 5.55 |

> **填表用射频频点找行**，不是 CF。

#### S4.3 四条硬规则（照做可避免全部错行错列）

1. **接收类截图必须换算** `射频 = CF + 34.5`（表见 S4.2）。
2. **同名文件陷阱**：`39.95.jpg / 39.975.jpg / 40.jpg` 在 `LNB到频谱仪` 与 `LNB到测控基带XS05` **两个目录都存在但内容不同**。
   判据：**电平**（−10~−12 = `B` 列；−20~−22 = `C` 列；−14~−16 = `D` 列）+ **仪表时间戳**（同一路径的截图时间戳是连续一串）。
3. **功率网页不显示频率**：只能按**文件名/用户说明**定频点；必要时问一句再填。
4. **重复投喂**：用 SHA256 判重，不重复填写，日志注明。

#### S4.4 首件必做：映射核对

```bash
node scripts/check_claims.js "<记录表.xlsx>"
```

| 输出 | 处理 |
|---|---|
| 全部打印 `✅ 与文档完全一致` | 映射可信，继续 S5 |
| 出现 `⚠️` / `✗` | **停止**。把输出发给工具维护人，按其实际行序修正 `_lib.js` 映射后再继续 |

#### S4.5 输出：单元格清单

每条一行，格式：

```
工作表 | 单元格 | 值 | 单位/口径 | 来源文件 | 判读依据(ΔdB/Δ时间/频点换算)
```

**清单未经复核人确认，不得进入 S5。**

### S5 编制 `spec_batchN.json`

`spec.json` 结构：

```json
{
  "sheet": "方向图",
  "mark":   ["D5","E5","J5"],
  "values": { "D5": -13.23, "E5": -16.58, "J5": 0.14146 },
  "texts":  { "U2": "数据来源截图", "U5": "37.5方位.jpg" },
```

### S7 校验（七道，少一道都不算核完）

> **全部通过才允许进入 S8。** 任一失败 → 回到 S4/S5 修正，不允许"带着问题归档"。

#### 第 1 道 · 回读校验

```bash
node scripts/verify_mark.js "<out.xlsx>" 方向图 D5 E5 J5
```

核对四件事：**值正确 / 字体色 / 是否加粗 / 填充色未被破坏**。

#### 第 2 道 · 逐格 diff

```bash
node scripts/diff_sheets.js "<原始记录.xlsx>" "<填报版.xlsx>" 方向图
```

**判据**：输出中"两表都有但值不同"必须是**无**（证明没有填错/串行）。

#### 第 3 道 · 全表复检（核心质量门）

```bash
node scripts/audit.js "<填报版.xlsx>" "<原始记录.xlsx>" --exempt=<来源列与日志行>
```

四类口径**必须全为"无"**，末尾必须打印：

```
问题 0 项 ✅
```

**四类口径的可执行定义**

| 类别 | 定义 |
|---|---|
| 漏标 | 原表空、本版有值、**且未红标** |
| 错标 | **红标但无值** |
| 值不一致 | 两表都有值且不同、**未红标** |
| 待填 | 蓝底格为空 **或** 落在已知输入区且为空 |

**审计口径的两个坑（务必避开）**

> ① **不要只用"蓝底"当判据** —— 前向链路标定表的输入格**没有底色**，只认蓝底会漏掉整张表；
> ② **不要跳过空格** —— 否则"蓝底仍待填"永远显示 0，看不出还缺什么。

**豁免清单**：来源列与批次日志行属**元信息格**，必须用 `--exempt` / `--exempt-file` 排除，否则"漏标"永远归不了零。

```bash
node scripts/audit.js "<填报版.xlsx>" "<原始记录.xlsx>" --exempt=方向图!A201,A202
node scripts/audit.js "<填报版.xlsx>" "<原始记录.xlsx>" --exempt-file=exempt.json
```

#### 第 4 道 · 公式复算与合格性判定

```bash
node scripts/analyze.js "<填报版.xlsx>"
```

全表公式复算 + 合格性判定（方向图增益、EIRP、G/T、跟踪 RMS、指标）。

#### 第 5 道 · 反算闭环（**最强证据**）

某行方位 + 俯仰都齐了以后，用 `R/S/T` 公式**手算 Gain**：

```
R = 31000 / ((N+O) × (J+K))     # 由 3dB 波束宽度算增益
S = 91000 / ((P+Q) × (L+M))     # 由 10dB 波束宽度算增益
T = 10 × LOG10((R+S) / 2)        # Gain
```

手算结果应与记录表 `T` 列**完全一致**。这是**行、列判定都正确的最强证据**。

#### 第 6 道 · 文件完整性

```bash
node scripts/zipcheck.js "<填报版.xlsx>"
```

ZIP 结构 + **每个条目 CRC32** + 所有 XML/RELS 良构。**改写 xlsx 后必做。**

#### 第 7 道 · 溯源核对（建议）

- 判图与目录文件是否**同一份**（SHA256）；
- 是否**重复投喂**（SHA256）；
- 是否**同名不同内容**（SHA256）。

## 10. 质量门与判定准则

### 10.1 指标门限（技术大纲）

| 项 | 要求 | 公式 / 常量 |
|---|---|---|
| EIRP | **≥ 69 dBW**（含天线罩） | `EIRP = P + G − L`，`L = Lf + Lfeed + Lc` |

| 方向图增益 | 无独立门限（供 EIRP / G-T 用） | `G ≈ 31000/(AZ3·EL3)`、`G ≈ 91000/(AZ10·EL10)` |
| 第一旁瓣 | 大纲未给限值（**仅要求记录**） | — |

## 12. 异常处理

### 12.1 目标文件被占用（Excel / WPS 正打开）

| 步骤 | 动作 |
|---|---|
| 1 | 存成带后缀的新名，如 `记录表_批1-9.xlsx` |
| 2 | 在回复/交接说明中**明确写出实际路径** |
| 3 | **不要反复重试** |

### 12.2 映射核对不符（`check_claims.js` 报 `⚠️`）

**停止作业**。把输出交给工具维护人，按其实际行序修正映射后再继续。**不得"凭感觉"填**。

### 12.3 口径争议（跟踪精度姿态 / 传感器）

**升级技术负责人裁决**，并留存书面确认。**不得由填表人自行选择字段。**

### 12.4 工具自测失败

不得用于正式数据。排查顺序：Node 版本 → 技能包完整性 → 是否被改动。修复后重跑 `tests/selftest.js`。

### 12.5 截图缺失 / 无法判读

| 情况 | 处置 |
|---|---|
| 某频点某方向截图缺失 | 该格**留空**并在日志行注明"缺 `<文件名>`"；**不得推算、不得借用邻频数据** |
| 小字模糊无法确认 | 放大 ≥2× 重读；仍不确定则**留空并标注**，交复核人处理 |
| 功率网页未标频率 | **问用户/操作员**确认频点，不得默认 |

### 12.6 写入被拒（公式格）

`fill_mark.js` 报告 `skipped` 且原因为公式格 → **正常**，该格本就不该手填。若 skipped 里出现**非公式格**，立即停止并排查。

### 附录 C · `keep.json` 模板（清空数据用）

```json
{
  "defaults": { "keepRows": [1,2,3,4,5], "keepCols": ["A","B","C"] },
  "sheets": {
    "方向图": { "keepRows": [1,2,3,4,5], "keepCols": ["A","B","C"] }
  }
}
```

> `clear_data.js` **默认保护内嵌图公式格**（`_xlfn.DISPIMG(...)`）。
> 实测某表含 **127 个**内嵌图格，若不保护会被整片抹掉。
> 保留规则：模板预置（表头 / 序号 / LO / 频率 / 行标签）+ 指定格；其余（**含公式格**）清空。
