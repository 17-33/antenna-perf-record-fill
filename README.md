# antenna-perf-record-fill

**信关站 / 天线电性能记录表 · 截图判读与填写（完整说明书）**

把频谱仪 / ACU / BUC 后台的测试截图，判读成数据，填进「1.8 m 一体化信关站电性能检测记录表」xlsx 的准确单元格，并完成红字标记、来源列、批次日志与全量校验。

**五层结构**

| 层 | 文件 | 内容 |
| --- | --- | --- |
| **规则层** | `SKILL.md` | 入口总览（导读 A–F）+ 判读总则、五张表结构、行↔频点、图表→列、SOP、七道校验、坑清单（§0–§20） |
| **执行层** | `scripts/*.js` | Node ≥ 12，**零 npm 依赖、纯离线**，自带 CRC32，不硬编码任何绝对路径 |
| **对照层** | `references/*.md` | 逐格对照表、换机型适配清单、切面速查卡、SOP 作业手册（人读版） |
| **模板层** | `assets/待填空表模板.xlsx` | **待填空表**：5 张表齐全、蓝底待填格已就位、公式缓存已抹并置 `fullCalcOnLoad`。配合 `new_case.js --template=` 即可开单 |
| **自证层** | `tests/selftest.js` | 67 项断言，含"故意破坏必须报错"的反向测试与 `$` 陷阱回归 |

## 一、核心功能

把「仪器截图 → 记录表单元格」做成**可复用、可校验、可追溯**的流水线，共六项能力：

| # | 能力 | 做什么 | 主要工具 |
| --- | --- | --- | --- |
| 1 | **判读** | FSW 零扫方向图 / BUC 后台功率页 / BAT Pro 跟踪面板 / 前向链路扫频 → 结构化读数 | `read_spectrum.js` + 三遍法（§18.12） |
| 2 | **定位** | 读数 → 五张表准确单元格（行↔频点、列↔ΔdB 语义、左/右·上/下、方位/俯仰切面） | §1 / §2 / §3 / §4 |
| 3 | **写入** | 填值 + 红字标记 + 来源列 + 批次日志；**只写副本，永不改原件** | `fill_mark.js` |
| 4 | **开单** | 用公司下发模板造"待填空表"：清数据输入区 + 抹公式缓存 + 置 `fullCalcOnLoad` | `new_case.js` / `clear_data.js` / `blank_formula_cache.js` |
| 5 | **校验** | 七道闭环：回读 / 逐格 diff / 公式复算 / 全表复检 / 缓存刷新 / 完整性 / 归档对账 | §16.5 / §8 |
| 6 | **归档** | 截图按公司惯例命名落位 + SHA256 对账 + `截图清单.md` + 核对报告 | `ingest.js` / §18.8 |

一句话：**任意数量的原始截图进去，一张干净、可追溯、通过全部校验的记录表出来。**

## 二、适用场景

**触发**（用户任一说即可）：

- 「把截图填到表里 / 填到对应位置」
- 「核对记录表数据与原始截图是否一致 / 检查一下对不对」
- 「只保留图里的数据 / 把其他数据删掉」
- 「开新机 / 整理第 N 号机数据 / 把这批图归档」

**输入物**：① 一张「N 号机一体化信关站电性能检测记录表」类 `.xlsx`（或公司下发模板）；② 一批测试截图（方向图 / 功率 / 跟踪精度 / 前向链路 / 旁证）。

**不适用**：非 xlsx 的通用文档编辑（走 `tencent-docs-routing`）；与电性能记录无关的图片整理。

**两种作业形态（先分清，见 §16.1）**：表里蓝底格是**空** → 正向填表；蓝底格**已有值** → 反向核对（逐格比对，**不改值**）。

## 三、执行步骤

### 3.1 单机作业十步（SOP）

```
① 承接开场（§0.5 四步：复述目标 → 亮思路 → 澄清模糊处 → 定交付形态）
        ↓
② 形态判定（§16.1）：正向填表 / 反向核对
        ↓
③ 建工作副本 + 截图归档（逐张 SHA256 判重，原件留档，§18.2 / §18.8）
        ↓
④ 前置闸门  check_pairs.js  ── 退出码 1 / 有异常 → 触发 §0.6 弃权规则：停手不填
        ↓
⑤ 三遍判读（§18.12）：read_spectrum 打底 → 窄列高倍 OCR 复核 → 异常放大目视
        ↓
⑥ 生成 spec（fill_mark 的输入；值做类型归一）
        ↓
⑦ 写入（fill_mark.js）→ 刷新公式缓存（refresh_cache.js，§17.5 / §20）
        ↓
⑧ 七道校验（§16.5）
        ↓
⑨ 报占用检查（§18.10）后写回；被 WPS/Excel 占用则另存新名并说明
        ↓
⑩ 归档命名 + 截图清单 + 核对报告 +（可选）整机目录打 zip 备份（§18.9）
```

### 3.2 一条命令的工作流（开新机）

```bash
NODE=node
SKILL=~/.workbuddy/skills/antenna-perf-record-fill

# ① 开单：建目录 + 写协议 + 造待填空表
$NODE $SKILL/scripts/new_case.js --machine=37 --root=$(pwd) --template=<公司下发件>.xlsx
#    仓库自带一份已脱敏的待填空表，可直接用（无需公司下发件）：
#    $NODE $SKILL/scripts/new_case.js --machine=37 --root=$(pwd) \
#          --template=$SKILL/assets/待填空表模板.xlsx

# ② 传图：图【原样】丢进 37号机/截图/_待归档/（别改名、别分类、别管顺序）

# ③ 归档：读 CF 定频点、读时间戳定切面、SHA256 判重
$NODE $SKILL/scripts/ingest.js --case=37号机 --dry-run   # 先看计划
$NODE $SKILL/scripts/ingest.js --case=37号机 --apply

# ④ 判读：两遍 OCR → read_spectrum → merge_judge → 终值 + 缺项报告
$NODE $SKILL/scripts/judge_batch.js --case=37号机 --batch=批1

# ⑤ 生成 spec（值已做类型归一）
$NODE $SKILL/scripts/make_spec.js --judge=37号机/批次/判读/判读_批1_终值.json --out-dir=37号机/批次/spec

# ⑥ 填表（写副本，不动原文件）
$NODE $SKILL/scripts/fill_mark.js 37号机/一体化*.xlsx 37号机/批次/填表1.xlsx 37号机/批次/spec/spec_方向图.json

# ⑦ 校验
$NODE $SKILL/scripts/analyze.js 37号机/批次/填表1.xlsx     # 必须「未发现不合格项 ✅」
```

> 想把 ③–⑦ 压成一条命令：`node scripts/run_case.js --case=37号机 --table=<xlsx> --batch=批1`。
> ③ 里若报「切面判不出来」，**别猜** —— 那是设计如此（缺对偶图或读不到仪器时间戳），补齐证据后重跑（§0.6）。

### 3.3 七道校验（少一道都不算核完，§16.5）

| 道 | 命令 | 通过判据 |
| --- | --- | --- |
| ① 他证 | `crosscheck.js <表> <判读.json>` | 逐格一致 / 差异清单为空 |
| ② 复算 | `analyze.js <表>` | 打印「未发现不合格项 ✅」 |
| ③ 自比 | `diff_sheets.js <原始> <归档版> <表>` | 「两表都有但值不同」= 0 |
| ④ 复检 | `audit.js <归档版> <原始> --exempt-file=审计豁免.json` | 打印「问题 0 项 ✅」 |
| ⑤ 完整性 | `zipcheck.js <原始> <归档版>` | 结构 + CRC32 + XML 良构全通过 |
| ⑥ 缓存 | `refresh_cache.js <表> <cells.json>` | 定点刷新 `<v>`，不破坏 XML |
| ⑦ 回读 | `verify_mark.js <表> <表名> <格…>` | 值 / 红字 / 加粗 / 底色均落位 |

> ⚠️ **任何写完 xlsx 的步骤之后都要跑 `zipcheck`** —— 它是唯一能抓住 XML 损坏的校验（§20）。

## 四、关键实现细节

### 4.1 xlsx 定点读写的六条规范（§12.3）

1. **解包**：xlsx = zip；读 `xl/workbook.xml`（表名↔rId）、`xl/_rels/workbook.xml.rels`、`xl/sharedStrings.xml`、`xl/styles.xml`。
2. **定位单元格**：`<row r="N">` 里找 `<c r="D5" s="30"><v>…</v></c>`；`t="s"` 去 sharedStrings 取值；**带 `<f>` 的是公式格，禁止写入**。缺 `r` 属性时按前格列号 +1 顺推。
3. **读色**：`s` → `cellXfs[s]` → `fillId`/`fontId` → `fills` 的 `fgColor rgb`（蓝 `FF00B0F0` = 需填写）/ `fonts` 的 `color rgb` + `<b/>`（红 `FFFF0000` + 粗 = 已按图填写）。
4. **写值与标记**：`styles.xml` 末尾追加红色加粗 `<font>`，再追加"复制原格 `<xf>`、只换 `fontId`"的 `<xf>`，改该格 `s` 后写 `<v>`。**不改动原任何 `<xf>`**；红字变体与 `<xf>` 均去重。
5. **清空**：非保留格替换成 `<c r="X" s="N"/>`（保样式、去 `<v>/<f>/<t>`），并更新 `<dimension>`。
6. **重打包**：按原条目顺序写回 zip；**未修改的条目直接复用原压缩字节** —— 大文件（含上百张图）既快又逐字节保真；CRC32 用自带查表法。

**公共内核 `_lib.js`**：ZIP 读写、CRC32、XML 工具、单元格引用换算、sheet 解析、样式追加、`Workbook` 类。所有脚本共用它 —— 判据下沉到内核，避免两份实现分叉（§17.2）。

### 4.2 `spec.json`（`fill_mark.js` 的输入）

```json
{
  "sheet": "方向图",
  "mark":  ["D5", "E5", "J5"],
  "values": { "D5": -13.23, "E5": -16.58, "J5": 0.14146 },
  "texts":  { "U2": "数据来源截图", "U5": "37.5方位.jpg" },
  "notes":  [ { "cell": "A25", "text": "批次1｜…｜源文件 37.5方位.jpg → 已填 D5 E5 J5" } ]
}
```

- `mark` 省略时 = 本次写入的全部格；**列出但没写值的格只上标记不改值**。
- 键支持区间：`"D5:D12": [v1, …, v8]`（按序铺开）或 `"D5:D12": 0`（同值灌满）。
- 顶层可为单作业、作业数组、或 `{ "jobs": [ … ] }`（串行写同一文件）。
- 公式格、**合并区影子格**（§16.3）一律拒绝写入，报告里列为 `skipped`。
- 来源列位置：方向图 `U`、EIRP `L`、跟踪精度 `D`、前向链路 `F`（用 `texts` 写）。
- 输入文件可带 **UTF-8 BOM 或 UTF-16LE**。样例见 `examples/spec_example.json`。

### 4.3 `keep.json`（`clear_data.js` 的输入）

```json
{ "defaults": { "keepRows": [1,2,3], "keepCols": [], "keepTextInLabelCols": false },
  "sheets": { "方向图": { "keep": ["A1:C21", "D1:Q4", "D21", "R1:T21"] } } }
```

- 用 **`keep` 反选**：列"要保留的"，而不是列"要清的"。
- `keepTextInLabelCols` 默认 true，前三列非纯数字文本当行标签保留。
- **默认保护内嵌图公式格**（`_xlfn.DISPIMG(...)`），`--no-protect` 可关。
- ⚠️ 开单时必须把 `keepCols` 默认的 `["A","B","C"]` 置空，否则会顺手保留落在前三列的输入格。样例见 `examples/keep_example.json`。

### 4.4 判读三总则 + 批量三遍法

> **图上这个数 → 先看 ΔdB 定列，再看 Δ时间正负定左右/上下，最后看射频频点定行。**

1. **时间→角度**：方向图为零扫（SWT 20 s、0.1°/s），`|Δ时间(s)| ÷ 10 = 角度(°)`。
2. **marker 按 ΔdB 语义认列，不按编号**：`M1`→M 列；`≈−3 dB`→3dB 列；`≈−10 dB`→10dB 列；`−14~−18 dB`→旁瓣列；`−20 dB 以下远区`→不填。
3. **符号定方向**：Δ时间为**负** = 方位左 L / 俯仰下 D；为**正** = 右 R / 上 U。
4. 接收类截图：**射频 = CF + 34.5 GHz**（本振），填表用**射频**频点找行。

**批量三遍法（§18.12）**：① `read_spectrum.js` 打底 → ② `ocr_image --region --scale=12` 只裁 X/Y 值列复核 → ③ 仅对异常/存疑格放大目视定论。**① 会丢 marker，所以 ② 不是可选项。**

### 4.5 公式缓存刷新与 `$` 陷阱（§17.5 / §20）

xlsx 公式格 = `<f>公式</f>` + `<v>上次结果</v>`。改输入格后 `<v>` **不会自动更新**：

- **①** `fill_mark.js` 写入后自动置 `fullCalcOnLoad`（`--no-recalc` 可关）→ Excel 打开即重算。
- **②** 归档前 `refresh_cache.js` 定点改写 `<v>` → 脚本 / diff / audit 也看到自洽文件。
- ⚠️ **必须用函数式替换** `xml.replace(re, () => m[1] + inner + m[3])`：公式里的绝对引用（如 `B$14`）在字符串替换中会被 JS 当**反向引用**展开，**静默写坏 XML**（§20）。改完必跑 `zipcheck`。

### 4.6 坑清单速查

| 坑 | 一句话 | 详见 |
| --- | --- | --- |
| 影子格 | 合并区非锚点格继承蓝底但**按设计该空**，写进去会静默丢数据 | §16.3 |
| OCR 咬字 | 基准 OCR 会咬错一位且方向不可预期 → 两遍独立 + 放大定论 | §16.4 |
| 缓存过期 | 表内值 ≠ 公式重算值 → 先问"上游本批动过吗" | §17.5 |
| 丢 marker | `read_spectrum` 在 RX 段丢单侧 marker → `merge_judge` 三源合并 | §17.6 |
| 开单残留 | 公司模板常**不是空表** → 先 `dump_xlsx` 确认 | §18.1 |
| 豁免上限 | 审计豁免要覆盖**会增长的区域**（来源列/日志区按整列） | §16.5.1 |
| 文件占用 | 覆盖前只看**写句柄**（`lsof … $4 ~ /w/`），预览面板的读句柄不算 | §18.10 |
| `$` 陷阱 | 改字节的脚本用函数式替换，`$` 是常规情况不是边界情况 | §20 |
| 切面错列 | 切面错则**整行错列且所有校验都抓不出来** → §0.6 弃权规则 | §0.6 / §19 |

## 六、脚本索引

> **21 个工具脚本 + 公共内核 `_lib.js` + 1 个 OCR 辅助（`ocr_image.swift`，macOS，非必需）**。
> 全部只接受显式路径参数，不含任何硬编码绝对路径。

### 开单 / 收图 / 判读编排

| 脚本 | 作用 | 退出码 |
| --- | --- | --- |
| `new_case.js` | **一键开单**：建目录骨架 + 生成《填写协议.md》《截图清单.md》《说明.md》+ `keep_<N>_blank.json` + `审计豁免.json`（整列豁免）；带 `--template` 时自动「留档原件 → clear_data → blank_formula_cache」造待填空表 | 0/1/2/3 |

## 八、已知边界 / 设计取舍

- **表内布局认定来自 §2。** 若客户模板行序不同，**先跑 `check_claims.js`**，按输出重定 spec 单元格；`analyze.js` 行号也需相应调整。
- **`audit.js` 四类口径**：漏标 = 原表空、本版有值且未红标；错标 = 红标但无值；值不一致 = 两表都有值且不同、未红标；待填 = 蓝底格为空或落在已知输入区且为空。来源列与批次日志行属元信息，用 `--exempt-file` 排除（覆盖**会增长的区域**，§16.5.1）。
- **清空后公式会消失**（§9.11）。最终定稿请从原始记录重建并回填全部批次，让公式自动长回来。
- 合并单元格的值落在左上角格（EIRP `G4`、GT `F4`）。
- 未实现：ZIP64、加密 xlsx、`.xls`（BIFF 二进制）——只处理常规 `.xlsx`/`.xlsm`。
- `read_spectrum.js` 仍无 `module.exports`、无单测（§17.4 第 1 条 / §17.6 根因）；`ocr_image.swift` 每次重编译（可加编译缓存）。

## 快速判断口诀

> **图上这个数 → 先看 ΔdB 定列，再看 Δ时间正负定左右/上下，最后看射频频点定行。**

- 时间→角度：方向图为零扫（SWT 20 s、0.1°/s），`|Δ时间(s)| ÷ 10 = 角度(°)`
- marker 按 **ΔdB 语义**认列，不按编号：`M1`→M 列；`≈−3 dB`→3dB 列；`≈−10 dB`→10dB 列；`−14~−18 dB`→旁瓣列；`−20 dB 以下远区`→不填
- 符号定方向：Δ时间为**负** = 方位左 L / 俯仰下 D；为**正** = 右 R / 上 U
- 接收类截图：**射频 = CF + 34.5 GHz**（本振），填表用射频找行
- 切面：**顺序定切面 → CF 定频点 → 时间戳验时序；顺序错则全批错列且校验无声**
